# AST-оптимизатор кода

**AST Optimizer for Python Code** — система для автоматического поиска и применения оптимизаций в Python-коде.

Система принимает Python-код, анализирует его структуру на уровне **AST (Abstract Syntax Tree)**, определяет возможные оптимизации, с помощью ML-модели оценивает потенциальную выгоду каждой трансформации, применяет выбранное изменение и сравнивает производительность исходной и оптимизированной версий.

---

# 1. Описание предметной области

## 1.1. Предметная область

Предметной областью проекта является **автоматическая оптимизация Python-программ**, в частности программ, реализующих последовательность операций формирования признаков (**feature engineering pipelines**) для задач машинного обучения.

Feature engineering pipeline представляет собой последовательность операций преобразования исходных данных в признаки, используемые ML-моделью. Такие операции могут включать:

* создание новых признаков;
* арифметические операции;
* преобразование столбцов;
* фильтрацию данных;
* применение функций;
* последовательное выполнение нескольких преобразований.

При увеличении количества операций Pipeline может содержать повторные вычисления, избыточные операции или другие конструкции, выполнение которых можно сделать более эффективным без изменения результата программы.

Традиционный подход заключается в использовании заранее определённого набора правил оптимизации. В рамках данного проекта статический анализ программы используется для поиска допустимых трансформаций, а ML-модель оценивает потенциальную производительность каждой из них.

---

## 1.2. Основные понятия предметной области

| Понятие                      | Описание                                                                              |
| ---------------------------- | ------------------------------------------------------------------------------------- |
| Python source code           | Исходный программный код, подлежащий анализу                                          |
| AST                          | Абстрактное синтаксическое дерево Python-программы                                    |
| AST node                     | Отдельный узел синтаксического дерева                                                 |
| AST feature                  | Числовая характеристика структуры программы                                           |
| Optimization candidate       | Потенциальная оптимизация, которую можно применить к программе                        |
| AST transformation           | Изменение структуры AST для оптимизации программы                                     |
| Cost model                   | ML-модель, оценивающая потенциальную выгоду трансформации                             |
| Speedup                      | Отношение времени выполнения исходной программы к времени выполнения оптимизированной |
| Benchmark                    | Измерение производительности программы                                                |
| Semantic validation          | Проверка сохранения результата выполнения после оптимизации                           |
| Feature engineering pipeline | Последовательность операций подготовки и формирования признаков                       |

---

## 1.3. Задача системы

Система должна автоматизировать следующий процесс:

```text
Python code
     ↓
Построение AST
     ↓
Анализ программы
     ↓
Поиск возможных оптимизаций
     ↓
Извлечение признаков
     ↓
ML-оценка каждой оптимизации
     ↓
Выбор трансформации
     ↓
Изменение AST
     ↓
Генерация Python-кода
     ↓
Проверка корректности
     ↓
Benchmark
     ↓
Отчёт о результате
```

# 2. Сценарии использования

## UC-01. Анализ Python-кода

**Цель:** получить структурную информацию о переданном Python-коде.

**Предусловие:** пользователь предоставил корректный Python-код.

**Основной сценарий:**

1. Пользователь передаёт Python-код системе.
2. `CodeParser` разбирает исходный код.
3. Формируется AST.
4. `ASTAnalyzer` выполняет обход дерева.
5. Извлекаются характеристики программы.
6. Система формирует результат анализа.

**Результат:** получено AST и набор характеристик программы.

---

## UC-02. Поиск кандидатов на оптимизацию

**Цель:** определить, какие оптимизации могут быть применены к программе.

**Предусловие:** AST программы успешно построен.

**Основной сценарий:**

1. `ASTAnalyzer` анализирует структуру AST.
2. Система обнаруживает потенциально оптимизируемые конструкции.
3. Для каждой конструкции определяется возможный тип трансформации.
4. Формируется список кандидатов.

---

## UC-03. Оценка оптимизаций

**Цель:** определить потенциальную производительность различных оптимизаций.

**Основной сценарий:**

1. Система получает AST-признаки.
2. Для каждого кандидата формируются признаки трансформации.
3. `MLOptimizer` получает набор признаков.
4. ML-модель предсказывает ожидаемый speedup.
5. Система формирует оценки для всех кандидатов.

---

## UC-04. Оптимизация программы

**Цель:** получить оптимизированную версию Python-программы.

**Основной сценарий:**

1. Система получает кандидатов на оптимизацию.
2. ML-модель оценивает каждый кандидат.
3. Выбирается трансформация с наибольшей прогнозируемой выгодой.
4. `ASTTransformer` изменяет AST.
5. `CodeGenerator` генерирует Python-код.
6. Оптимизированный код передаётся на проверку корректности.

**Результат:** оптимизированный Python-код.

---

# 3. Функциональные требования

## FR-01. Работа с исходным кодом

**FR-01.1.** Система должна принимать Python-код в качестве входных данных.

**FR-01.2.** Система должна проверять синтаксическую корректность входного Python-кода.

**FR-01.3.** Система должна преобразовывать корректный Python-код в AST.

**FR-01.4.** Система должна генерировать Python-код из изменённого AST.

---

## FR-02. Анализ AST

**FR-02.1.** Система должна выполнять обход AST.

**FR-02.2.** Система должна определять основные характеристики AST.

**FR-02.3.** Система должна определять количество и типы используемых конструкций Python.

**FR-02.4.** Система должна обнаруживать повторяющиеся и потенциально оптимизируемые конструкции.

---

## FR-03. Поиск оптимизаций

**FR-03.1.** Система должна формировать список потенциальных оптимизаций.

**FR-03.2.** Каждая оптимизация должна содержать информацию о типе трансформации и соответствующем фрагменте AST.

**FR-03.3.** Система должна поддерживать несколько типов AST-трансформаций.

**FR-03.4.** Система должна позволять расширять набор поддерживаемых оптимизаций.

---

## FR-04. ML-оценка

**FR-04.1.** Система должна извлекать числовые признаки из AST.

**FR-04.2.** Система должна формировать признаки конкретной трансформации.

**FR-04.3.** ML-модель должна прогнозировать потенциальную выгоду оптимизации.

**FR-04.4.** Система должна рассчитывать оценку для каждого кандидата.

**FR-04.5.** Система должна выбирать трансформацию на основании прогнозируемой выгоды.

---

## FR-05. AST-трансформация

**FR-05.1.** Система должна применять выбранную трансформацию к AST.

**FR-05.2.** Система не должна изменять исходный AST при формировании оптимизированной версии.

**FR-05.3.** Система должна формировать отдельную оптимизированную версию AST.

---

## FR-06. Проверка корректности

**FR-06.1.** Система должна запускать исходную и оптимизированную версии на одинаковых тестовых данных.

**FR-06.2.** Система должна сравнивать результаты выполнения.

**FR-06.3.** Система должна учитывать допустимую числовую погрешность при сравнении результатов.

**FR-06.4.** Система не должна считать оптимизацию успешной, если проверка корректности не пройдена.

---

## FR-07. Benchmark

**FR-07.1.** Система должна измерять время выполнения исходной программы.

**FR-07.2.** Система должна измерять время выполнения оптимизированной программы.

---

# 4. Нефункциональные требования

## NFR-01. Производительность

Система должна выполнять анализ AST без существенного увеличения времени обработки программы.

Время анализа должно быть существенно меньше времени benchmark для программ, для которых выполняется измерение производительности.

---

## NFR-02. Корректность

AST-трансформация не должна считаться успешной без прохождения проверки семантической эквивалентности на тестовых данных.

---

## NFR-03. Расширяемость

Архитектура должна позволять добавлять новые виды оптимизаций без существенного изменения существующих компонентов.

Новая оптимизация должна реализовываться как отдельная трансформация.

---

## NFR-04. Модульность

Основные компоненты системы должны быть разделены:

```text
Parser
Analyzer
ML Optimizer
Transformer
Code Generator
Benchmark
```

Изменение одного компонента не должно требовать изменения внутренней реализации остальных компонентов.

---

## NFR-05. Воспроизводимость

Результаты benchmark должны быть воспроизводимыми при одинаковых:

* исходном коде;
* входных данных;
* настройках среды;
* параметрах benchmark.

---

## NFR-06. Интерпретируемость

Для каждой предложенной оптимизации система должна предоставлять:

* тип трансформации;
* участок программы, к которому она применяется;
* предсказанный speedup;
* фактический speedup после benchmark.

---

## NFR-07. Тестируемость

Каждый основной компонент должен иметь возможность тестироваться независимо:

```text
CodeParser
ASTAnalyzer
MLOptimizer
ASTTransformer
CodeGenerator
Benchmark
```

---

# 5. Общая архитектура системы

Система состоит из следующих основных компонентов:

### Code Parser

Отвечает за преобразование:

Python source code → AST


### AST Analyzer

Отвечает за:

* обход AST;
* извлечение характеристик;
* обнаружение оптимизируемых конструкций;
* формирование кандидатов.

### ML Optimizer

Отвечает за:

* формирование признаков;
* применение обученной ML-модели;
* оценку потенциального speedup;
* выбор трансформации.

### AST Transformer

Отвечает за изменение AST согласно выбранной оптимизации.

### Code Generator

Преобразует оптимизированный AST обратно в Python-код.

### Benchmark

Измеряет фактическую производительность исходного и оптимизированного кода.
